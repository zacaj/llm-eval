# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A harness for running the [aider polyglot benchmark](https://aider.chat/docs/leaderboards/) (225 Exercism exercises: Python, Go, Rust, JS, Java, C++) against **local LLMs served by llama.cpp** (or Strata / OpenRouter), and tracking the results across many models/configs. There is no application code to build or unit-test — the work is bash orchestration, a Docker image, and a few Python patches/scripts.

## Commands

All via `./run.sh <command> [exercise-substrings...] [flags]` (see the big header comment in [run.sh](run.sh) for the full list):

```bash
./run.sh build                  # build the Docker image (aider + exercises + patches)
./run.sh smoke                  # 1 fixed python exercise
./run.sh quick                  # 5 fixed python exercises
./run.sh quick zipper leap      # bare words = aider --keywords substrings, not a model name
./run.sh random 5               # random sample (the others are deterministic on purpose)
./run.sh python | polyglot | full
./run.sh fromfile results/shortlist-7.txt [--clean|--resume]   # run just the listed exercises
./run.sh stats <run-dir>        # regenerate stats for a finished run
./run.sh shell                  # shell inside the container
```

Everything is configured by env vars, not positional args: `MODEL` (llama `--alias`; a value containing `/` is used as a full litellm spec, e.g. `openrouter/<vendor>/<slug>`), `TARGET=llama-nas|strata`, `EDIT_FORMAT` (whole|diff|udiff…), `TRIES` (default 6), `MAX_TOKENS`, `MAX_DUR`, `REASONING_EFFORT=low|medium|xhigh`, `TEMPERATURE` (`server` = send none), `SEED`. Flags starting with `-` are forwarded to aider's `benchmark.py`.

[sweep.sh](sweep.sh) runs `run.sh` over several model/server configs in turn, swapping the persistent `llama-cpp` compose service via `/mnt/llm/model-configs/mcfg.py` (outside this repo). `CONFIGS` is a configs.txt path or a comma list of GGUFs; `SKIP_EXISTING=1 SEED_TRIES=2` gap-fill and auto-retry 100%-failing exercises. Its header comment documents the format.

## Architecture

- **Eval host ≠ model host.** The aider container runs here; the model server is remote (the NAS, or Strata on its Windows host). `TARGET` in run.sh selects base URL, health URL, and how server settings (`srv.*` columns) are captured — `docker inspect` over `ssh://$NAS_HOST` for llama-nas, the `/props` endpoint for Strata. llama-nas requests go through a `:3002` prompt-logger proxy; health probes hit `:8080` directly.
- **Docker image** ([Dockerfile](Dockerfile)) clones upstream aider and applies [patches/](patches/) to `benchmark/benchmark.py` at build time. Each patch fixes a real failure mode (unbounded test output, no per-exercise wall clock, orphaned grandchild test processes, a hung `coder.run()` retrying forever, chat-history growth) and its docstring explains why. If you change harness behaviour, add/edit a patch and rebuild rather than editing the container.
- **Per-run model settings.** run.sh writes an aider model-settings YAML per `MODEL_SLUG`/`SAMPLING_SLUG` (extra_params: seed, temperature, reasoning budget) so concurrent runs of different models/seeds don't clobber each other. `REASONING_EFFORT` is a *bundle* (thinking budget + max tokens + duration multiplier), not just a hint.
- **Result tracking.** While a run executes, `track_per_test` polls `.aider.results.json` files and `track_aggregate` summarises; both append to `results/eval-results-per-test.tsv` / `results/eval-results.tsv` (flock-guarded via the `.lock` files). `refresh_viz` then runs `results/generate_viz_data.py` to rebuild `results/eval-viz.html` from `results/eval-viz-template.html` — edit the template, not the generated HTML. The generator turns TSV rows into runner-neutral attempt records through per-runner adapters (`aider_attempt`, `harbor_attempt`), and each attempt's end reason and flags come from [results/outcomes.py](results/outcomes.py). Harness failures are excluded from the stats. `harbor-trials.tsv` comes in as separate task variants (`harbor`, `harbor-tc`), labeled `·A`/`·H`/`·HT`. Model keys are assigned over both runners' rows in one pass (`assign_model_keys`, on gguf + shared samplers/effort; the token budget is ignored), so a Harbor trial joins the aider model it matches. Run.sh's `hist_*` columns are counts taken from each attempt's chat history.
- **Shortlists.** `results/*.txt` are exercise lists for `fromfile` (`[language] exercise [max_tries max_dur]`, `#` comments). Exercises are grouped by effective (tries, max_dur) and run as separate `benchmark.py` invocations into the same results dir. `shortlist-*.txt` carry baseline pass-try annotations used by `compare_to_baseline`.
- **`extra-exercises/`** holds `full-*` variants (java word-search, go paasio) where helper files normally hidden from the model are moved into the chat; mounted read-only through docker-compose.yml.

## Harbor (agentic evals) — `harbor/`

A separate, independent runner for [Harbor](https://github.com/laude-institute/harbor) (agents like `claude-code` / `terminus-2` in sandbox containers). It deliberately shares nothing with run.sh's selection/seed/skip machinery — use Harbor's own `-i <glob>` / `-l` / `-k` / `-n`.

```bash
./harbor/harbor.sh gen                                         # regenerate harbor/tasks/aider_polyglot (random oracle secret)
./harbor/harbor.sh run claude-code -i 'polyglot_python_*' -l 5 # BASE_URL / MODEL env; -n 1 default
./harbor/harbor.sh run oracle -i 'polyglot_rust_*'             # verifier sanity check, no model
./harbor/harbor.sh run claude-code --list harbor/lists/smoke-per-language.txt -k 3   # run.sh-format lists work too
BUDGET=20000 MAX_DUR=900 ./harbor/harbor.sh run terminus-2 -i polyglot_python_bowling   # per-trial output-token cap + agent wall clock
./harbor/harbor.sh collect                                     # harbor/jobs/* -> results/harbor-trials.tsv (model trials; oracle/nop checks -> harbor-trials-checks.tsv)
```

- `harbor/adapters/aider_polyglot/` is a **fork** of Harbor's upstream adapter; every change is marked `(fork)`. Upstream only ran the first test for Rust/JS/C++ (ignored/xtest/RUN_ALL_TESTS), C++ effectively scored "compiles", C++ build failures produced no reward, Java missed `@Disabled` variants, and the oracle payload sat in the agent's workspace with a public key.
- Verifier writes `reward.json`: `reward` (binary, upstream-comparable) plus `tests_passed/total/frac/parsed/expected`. Tests that never ran (crash, aborted binary, timeout) count as failed: `tests_total` is never below the task's `tests/expected_total`, baked in at gen from [harbor/expected-totals.tsv](harbor/expected-totals.tsv) (collect.py merges in every reward=1 oracle trial). `harbor.sh run` fills gaps itself: selected exercises with no known total get an oracle job first (a `CHECK` job, before any SWAP_CMD), then their tasks are regenerated; `EXPECTED_PREFILL=0` skips it. Passes are counted per test line (pytest -v, `cargo test` lines + `running N tests`, go -v) so a run that died partway keeps its passes. Tasks without a known total still undercount on Go panics / C++ crashes; collect.py's `tests_frac_adj` backfills from oracle trials.
- harbor.sh snapshots the model server's output-affecting settings (before + after the run) into `jobs/<job>/server-settings.txt`, using the same functions as run.sh's srv.* columns (now in [server-capture.sh](server-capture.sh), sourced by both); collect.py adds them as srv.* columns.
- **One Harbor job per `harbor.sh run`**, whatever mix of datasets / time limits / attempt counts: harbor.sh resolves the tasks itself (list rows, `-i` globs, SKIP_EXISTING remainders) and passes `-c jobs/<job>/harbor-tasks.json` listing each task path once per attempt. A task whose limit differs from its task.toml runs from a copy with the limit written in, `tasks/_dur/<secs>/<same name>` (collect.py / skip_existing.py read the limit from the task.toml a trial actually ran). Harbor's `-i`/`-l` aren't used for selection.
- Job names: `<run id MMDD-HHMMSS or JOB_NAME>_<tasks>_<cc|t2|agent>[-b<budget>]` (older jobs may have `_d<secs>`/`_k<n>`); `<tasks>` lists up to 4 short names (`go-bowling.tc6`), else `<list name>.<count>[.tc]`. Model and settings live in the job config / collect.py columns, not the name.
- Claude Code is pinned: the task images pre-install `ARG CC_VERSION` (task-template/Dockerfile), and harbor.sh passes it as `--ak version=` so Harbor skips its slow per-trial install (apt nodejs over a flaky mirror hit the 360s setup timeout). Bump it there and regenerate the tasks.
- `SKIP_EXISTING=1` makes `-k N` mean "ensure N graded attempts per task": [harbor/skip_existing.py](harbor/skip_existing.py) counts matching earlier trials across all jobs (same agent+version/BUDGET/output-affecting server settings, and same time limit -- or, for trials that ended on their own, an agent runtime within the requested limit; INVALID and ungraded infra errors excluded) and harbor.sh runs only the remainder, so rerunning a command resumes it. (`uvx harbor@0.25.0 job resume -p harbor/jobs/<job>` resumes one interrupted job in place.)
- `EFFORT` (default `low`) sets Claude Code's effort (`CLAUDE_CODE_EFFORT_LEVEL`; its own default `high` resolves to `xhigh` on Strata). On Strata, harbor.sh probes through the proxy with a request shaped like Claude Code's and records what Strata resolved (`srv.eff.reasoning_effort/_budget/_budget_source`, via `probe_strata_reasoning` in server-capture.sh); the thinking cap comes from the proxy's `cap_reasoning_budget` filter (4000) unless the caller sets one. Strata jobs from before this ran at xhigh/4000 (backfilled, `_source=backfilled`).
- **Server slowdowns**: the eval proxy logs each request's `duration_ms`/`tok_s`. collect.py takes the job's median tok/s (requests with 300+ output tokens) as baseline; a request under 30% of it is "slow" and its time beyond baseline speed is `slow_lost_sec`. A timed-out trial with lost time is auto-marked INVALID (`auto:` reason, so SKIP_EXISTING reruns it); a finished one gets `agent_sec_adj` = agent_sec - lost. Only trials whose jobs started after this have timings.
- **Progress sampling** ([harbor/progress_sampler.py](harbor/progress_sampler.py), started by run_job for model agents): every `PROGRESS_INTERVAL` s (default 180, 0 = off) each running trial's `/app` is copied out (minus target/build) and graded by the task's own test.sh in a separate container from the same image (hidden tests mounted read-only, `--cpus 2`, `PROGRESS_TIMEOUT` default 90) -> `<trial>/progress.tsv`. The agent sees nothing and no run-tests calls are used. collect.py: `prog_samples`, `prog_first_pass_sec`, `prog_best_frac`, `prog_last_frac`.
- **Progress on a budget axis**: tc tasks' run-tests calls are logged per call (ms start/end, passed/total) and the verifier keeps that log as `verifier/run-tests-log.tsv`. collect.py joins both calls and progress samples to the trial's eval-proxy requests and writes `results/harbor-progress.tsv`, one row per point with `requests_before` / `out_tokens_before` (completed requests up to the graded moment). It also adds `first_pass_requests` / `first_pass_out_tokens` to harbor-trials.tsv. Prefer these over the `*_sec` columns, since server speed varies (see [viz-harbor-plan.md](viz-harbor-plan.md)).
- **Harness checks**: oracle/nop trials, and every trial of a job with a `CHECK` file (first line = reason; `CHECK="reason" harbor.sh run ...` writes it), go to `results/harbor-trials-checks.tsv` instead of `harbor-trials.tsv` (`check` column = reason). Oracle trials still supply `tests_total_oracle`.
- **Invalidating trials**: put an `INVALID` file (first line = reason) in `harbor/jobs/<job>/<trial>/`; collect.py copies the reason into the `invalid` column. Harbor's own result.json is left untouched, so `uvx harbor view` still shows them as normal. Filter `invalid` rows out of comparisons.
- collect.py's `thinking_cutoffs` / `final_turn_cutoff` take the best source available, recorded in `thinking_cutoff_source`. `proxy` = the eval proxy's `reasoning_tokens >= reasoning_budget` (Strata reports both per request). `marker` = the fixed line Strata ends a budget-cut thinking block with (older jobs). `length-est` = llama, which reports neither and cuts mid-sentence: a block of 12k+ chars not ending a sentence, calibrated on Strata. Old llama jobs ran under the NAS proxy's default 4000 thinking cap, backfilled into server-settings.txt as `srv.eff.reasoning_budget_source=backfilled` (skip_existing ignores `*_source` keys). `final_no_action` also comes from the Claude Code log; `final_turn_cutoff` + `final_no_action` = the model was cut off, wrote its plan as text and stopped, which Claude Code takes as done.
- collect.py counts tool calls, malformed/unparsed tool calls, final-message-is-tool-markup (ends Claude Code episodes early), edits, build/test runs from the ATIF `agent/trajectory.json`.
- **Eval proxy** ([harbor/eval_proxy.py](harbor/eval_proxy.py)): harbor.sh starts one per job on this host (containers reach it at `EVAL_PROXY_HOST`, default our LAN IP toward the NAS) and points the agents at it; it forwards to `BASE_URL` (the NAS prompt-logger proxy, which stays about the engine: filters, reasoning cap, routes). It enforces `BUDGET` (`X-Eval-Budget` from the agent; clamps `max_tokens`, rejects with "eval token budget exhausted"; upstream gets `X-Eval-Budget: 0` = eval mode, no routes, no second budget) and logs one row per request to `jobs/<job>/eval-proxy.tsv` with what Strata reported in `strata_effective` (effort, thinking budget, reasoning/answer tokens, `budget_cutoff`). collect.py sums those per trial into `px_*` columns, matched by Claude Code's session uuid / terminus-2's session header. Jobs from before it have empty `px_*` columns; their budget was enforced by the NAS proxy's eval mode (`logs/eval-budget.tsv` there).
- **Test-calls tasks** (`harbor/tasks/aider_polyglot_tc/polyglot_<lang>_<ex>__tc<N>`, made by `harbor.sh gen-tc`): agent runs non-root and gets a `run-tests` command for the still-hidden tests, N calls max (stated in the instruction; the agent's processes are killed after the last call). `--list` rows with a try count (3rd column) run as `__tc<count>` automatically (missing ones are generated); `TC=1`/`TC=0` forces all/none. Mixed lists run as separate jobs.
- List `max_dur` → that task's agent time limit (via the `tasks/_dur/` copies above); `max_tries` has no equivalent. `MAX_DUR_SCALE` (number or `auto`, as in run.sh; the decode probe `measure_decode_tps` now lives in server-capture.sh) multiplies every limit, and the scaled value is what job names, the `max_dur` column and SKIP_EXISTING see. `-k` attempts get independent samples: no seed is sent and Strata picks a random one per request.
- Harbor builds one image per trial (deleted after); parallel builds of several toolchains need tens of GB free on `/var`.

## Gotchas

- Default sampling was historically **greedy** (aider sends temperature 0), making "reruns" byte-identical replays; now `TEMPERATURE=0.6` + fixed `SEED`. Compare pass *rates* across several seeds, not single pass/fails. See [mtp-off-runaway-generation.md](mtp-off-runaway-generation.md) and [moe-cache-off-required.md](moe-cache-off-required.md) for server-config findings that affect results.
- [viz-harbor-plan.md](viz-harbor-plan.md): plan (not yet implemented) for putting Harbor into the viz: attempt records, censored pass-within-budget scoring on token/turn axes, end-reason + flag taxonomy.
- `results/` is gitignored; [todo.md](todo.md) is a running log of queued/finished eval runs and findings.
- Reusing a results dir: `guard_reuse` / `auto_clean` decide whether `--clean` is needed — `smoke/quick` auto-clean, `python/full` don't.
